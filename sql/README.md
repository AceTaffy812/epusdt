# 数据库安装与更新

项目不会在启动时自动创建或修改数据库表，需要手动执行 [`sql`](.) 目录中的 SQL 文件。数据库连接信息请参考 [`src/.env.example`](../src/.env.example) 和实际运行目录中的 `.env`。

## 全新安装

1. 创建项目使用的 MySQL 数据库，并配置好字符集。
2. 按文件名日期从早到晚，依次执行 [`sql`](.) 目录中的全部 SQL 文件。
3. 确认所有 SQL 执行成功后，再配置并启动应用。

全新安装不要只执行某一个增量文件。基础表结构和后续结构调整都需要执行，具体以当前 [`sql`](.) 目录中的文件为准。

## 已有项目更新

1. 停止应用，避免更新期间继续创建订单或写入数据库。
2. 备份当前数据库，并确认备份可用。
3. 查看当前数据库已经执行到哪个版本。
4. 按日期顺序执行尚未执行的 SQL 文件，不要重复执行已经成功执行过的文件。
5. 确认数据库更新成功后，再替换应用文件并启动新版本。

每次发布如果包含数据库变更，会在本目录新增一个按日期命名的增量 SQL 文件。已有项目只需要执行从当前版本开始缺失的增量文件；不要重新执行基础表结构文件。

## 更新记录

- 20251209.sql 基础数据库，对应 v0.0.7 版本。更早的版本不再维护。
- 20261005.sql 对应 v0.1.0 版本。

## 注意事项

- SQL 文件可能不是幂等脚本，重复执行可能导致报错或重复变更。
- 生产环境执行前务必备份数据库，不要跳过失败的 SQL。
- 如果当前数据库版本不明确，或实际结构与项目版本差异较大，请先核对数据库结构和备份，再决定升级顺序。
- 数据库更新完成后，再启动对应版本的应用；环境变量配置请参考 [`wiki/ENV.md`](../wiki/ENV.md)。

**除非你是专业人士，否则请按最新版本和最新数据库状态使用，且不要尝试降级。**
